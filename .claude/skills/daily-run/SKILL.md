# daily-run — 今日の仕事

「今日の仕事始めて」で呼ばれる。以下を順に実行する。

## 実行前に

1. `CLAUDE.md` を読む
2. `config.json` を読み、今日の設定を確認してユーザーに1行で伝える

```
本日の設定: 3件処理 / 送信チャネル=draft_only / エリア=〇〇区
```

## フロー

```
1. find-prospects     見込み客を探す（最大10件、既存はスキップ）
        ↓
2. new-preview        1店ずつ試作サイトを作る（5段階）★1店ずつ完結させる★
        ↓
3. publish-preview    GitHub Pages に公開してURLを発行
        ↓
4. send-outreach      営業メッセージを作って送信（1日10件まで）
```

## ★重要★ 1店ずつ完結させる

**複数店を同時に作らない。** 1店を「作成→公開→送信」まで完結させてから次の店に移る。

理由：
- 複数店の情報を同時にコンテキストに載せると、**店名や住所が混ざる事故**が起きる
- 1店ずつなら、途中で止まっても中途半端な状態が残らない

`config.json` の `daily.max_new_sites`（初期値 **3**）の件数だけ繰り返す。

## セッションが重くなったら

1店終わるごとに、進捗をファイルに保存しておく。
出力が遅くなったり不安定になったら、そこで区切ってユーザーにこう伝える：

> 〇件完了しました。セッションを新しくしてから続きをやると安定します。

## 完了報告

最後に次を報告する。

- 見つけた件数 / 新規に作った件数 / 公開した件数 / 送った件数
- 公開したURLの一覧
- スキップした店とその理由
- 次にやるべきこと

## 守ること

- `config.json` の上限値（`max_new_sites` / `daily_send_cap`）を勝手に上げない
- エラーが出たら無限にリトライせず、そのまま報告する
- 苦情の返信が1件でもあれば、残りの送信を止めて報告する
