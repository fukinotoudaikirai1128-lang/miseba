# daily-run — 今日の仕事

「今日の仕事始めて」で呼ばれる。

## 実行前に

1. `CLAUDE.md` を読む
2. **`brand/LEGAL.md` を読む**
3. `config.json` を読み、今日の設定を1行で伝える

```
本日の設定: 3件 / 手段=はがき / エリア=〇〇区 / 上限=10件
```

---

## フロー

★2026-08-21 変更★ **勝手に他店の試作サイトを作って公開する運用はやめました。**
実在の店のページを無断で公開すると、不正競争防止法・商標法まわりの危険があり
（LEGAL.md §2）、限定公開にする手段も無料では確保しにくいためです。
いまは「**チラシで入口だけ配り、興味を持った人にだけ作る**」形にしています。

```
0. ユーザーがGoogleマップで店を探す（★人の手★）
        ↓
1. find-prospects     貼られた情報を選別・裏取り・登録
        ↓
2. make_flyer.py      A4チラシを作る（ミセバのサイトのQRだけを載せる）
        ↓
3. ★ユーザーが投函★  印刷してポストへ。紙代のみ
        ↓
   ──── ここで一旦終わり。反応を待つ ────
        ↓
4. 連絡が来たら       new-preview でその店の試作を作る（ここで初めて作る）
        ↓
5. publish-preview    公開してURLを渡す（相手の同意があるので公開してよい）
        ↓
6. send-outreach      必要なら文面を作る
```

**2〜3で1日の作業は終わりです。** 試作サイトは作りません。
興味のない店のために作る手間がなくなり、法務上の危険もなくなります。

## ★重要★ 1店ずつ完結させる

**複数店を同時に作らない。** 1店を「作成→公開→はがき」まで完結させてから次へ。

理由：
- 複数店の情報を同時に扱うと、**店名や住所が混ざる事故**が起きる
- 1店ずつなら、途中で止まっても中途半端な状態が残らない

`config.json` の `daily.max_new_sites`（初期値 **3**）の件数だけ繰り返す。

## 各ステップの実行コマンド

```bash
python3 scripts/build_site.py <slug>          # STEP1〜3（骨組み・デザイン・画像）
# → STEP4（文言）と STEP5（最終チェック）は Claude が手で行う
python3 scripts/preview.py <slug>             # ブラウザで目視確認
python3 scripts/publish.py <slug>             # 検証 → docs/p/ にコピー（公開はNetlifyへ手動アップ）
python3 scripts/make_postcard.py <slug>       # はがきHTMLを作る
```

`publish.py` は GitHub に push しません。`prospects/` と `docs/p/` は .gitignore 済みです。
公開は https://app.netlify.com/drop に `docs` フォルダをドラッグ＆ドロップする作業で、
**これはユーザーの作業**です。Claude は代行しません。

## セッションが重くなったら

1店終わるごとに進捗を保存する。出力が遅くなったら区切って伝える：

> 〇件完了しました。セッションを新しくしてから続きをやると安定します。

  □□接骨院   → 広告規制の対象業種

  2. 反応があったら報告してください

---

## 守ること

- `config.json` の上限（`max_new_sites` / `daily_send_cap`）を勝手に上げない
- **除外業種のチェックを飛ばさない**（`brand/LEGAL.md` §2）
- エラーが出たら無限にリトライせず、そのまま報告する
- **苦情の返信が1件でもあれば、残りを全部止めて報告する**
- はがきは**Claudeが投函できない**。印刷と投函はユーザーの作業だと明示する
