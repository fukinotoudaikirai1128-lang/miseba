# new-preview — 試作サイトを段階的に作る

## 前提

- `CLAUDE.md` のルールを**必ず先に読む**こと。特に §1（絶対制約）と §5（段階実行）。
- 作業対象は `prospects/<slug>/` **1フォルダのみ**。他の店のフォルダは開かない。

## 入力

`prospects/<slug>/info.json` に店舗情報がある。無ければ `find-prospects` を先に実行する。

```json
{
  "slug": "yamada-roofing",
  "name": "山田屋根工事",
  "industry": "roofing",
  "address": "東京都〇〇区1-2-3",
  "phone": "03-1234-5678",
  "rating": 4.6,
  "review_count": 8,
  "hours": ["月〜金 8:00〜18:00", "土 8:00〜17:00", "日 定休"],
  "review_highlights": ["雨漏りをすぐ直してくれました", "見積もりが明確でした"],
  "maps_url": "https://maps.google.com/..."
}
```

**`info.json` に無い情報はサイトに書かない。** これが最重要ルール。

---

## 手順

### STEP 1〜3 — 骨組み・デザイン・画像（スクリプトで一括）

この3段階は機械的なので、補助スクリプトで一気に済ませる。

```bash
python3 scripts/build_site.py <slug>
```

これで `prospects/<slug>/site/index.html` が生成される。中身：
- `info.json` の `industry` に応じた業種カラー・見出し・お困りごと・サービス3種
- Unsplash画像、スマホ固定CTAバー、スクロールアニメーション、`noindex`

**試作は1ページのみ**（`CLAUDE.md` §4 参照）。複数ページにしない。

**完了判定**：スクリプトが「未置換のプレースホルダー」警告を出していない。

---

### STEP 4 — 文言

`info.json` の実データに差し替える。**ここが一番事故が起きやすい。**

差し替える項目：
- 店名、住所、電話番号、営業時間
- Googleの評価（「Googleマップで★4.6（8件）の評価をいただいています」のように出典を明記）
- 口コミ抜粋（`review_highlights` のみ。短く引用）

**差し替え後に、必ず生成した全ページを読み返して、以下がゼロであることを確認する：**

- 創業年 / 営業年数 / 施工実績数 / 従業員数
- 資格 / 認定 / 受賞歴
- 料金 / 価格 / 割引
- 「地域No.1」「実績多数」など裏付けのない表現
- `info.json` に無い対応エリア

**1つでも見つけたら削除する。** セクションごと消してよい。

**完了判定**：上記の禁止事項が1つも書かれていない。

---

### STEP 5 — 最終チェック

`CLAUDE.md` §5 のチェックリストを1項目ずつ確認する。

さらに、**実際にブラウザで開いて目視確認する**：

1. `scripts/preview.py <slug>` でローカルサーバーを起動
2. ブラウザツールで `http://localhost:8000/` を開く
3. スクリーンショットを撮る（スマホ幅 375px / PC幅 1440px の2枚）
4. 崩れ・文字化け・画像切れがないか自分の目で確認する
5. 問題があれば修正して再確認

**完了判定**：スクリーンショット2枚で問題が見つからない。

---

## 完了後

`prospects/<slug>/info.json` に `"status": "site_ready"` を書き込む。
次は `publish-preview` スキルで公開する。

## 注意

- **STEPを飛ばさない。** 一気に全部作ると品質が落ちる（これは実証済みの経験則）。
- 各STEPの完了判定を満たさないまま次に進まない。
- 会話が長くなって出力が不安定になったら、そこまでをファイルに保存して
  ユーザーに「セッションを新しくすることを勧める」と伝える。
