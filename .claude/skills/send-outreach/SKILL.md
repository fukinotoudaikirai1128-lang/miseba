# send-outreach — 営業の文面を作る

## 最初に読む

**必ず `brand/LEGAL.md` を読んでから作業すること。** 連絡手段には法的な制約があります。

---

## 使える連絡手段（2026年8月時点）

| 手段 | 可否 | 備考 |
|---|---|---|
| **郵便はがき** | ⭕ **本命** | 規制なし。85円／通 |
| **電話** | 🔺 | その場で契約を取らない。URLを伝える方法を聞くだけ |
| メール | ❌ | 特定電子メール法。相手にサイトが無い＝例外が使えない |
| Googleマップのメッセージ | ❌ | **2024年7月31日に機能終了。存在しない** |
| SNSのDM | ❌ | 各サービスの規約でスパム扱い |

**返信の受け皿は LINE公式アカウント**（`https://lin.ee/VGyzGYv`）。
はがきのフッターに小さなQRが自動で入ります。こちらから送る手段ではなく、
相手から来てもらう入口として使うこと。

> ❗ 以前は「Googleビジネスプロフィールのメッセージ機能」が使えましたが、
> Googleが2024年7月31日に提供を終了しました。**この経路は選べません。**

---

## ブレーキ（勝手に緩めない）

| 項目 | 値 | 理由 |
|---|---|---|
| 1日の送信上限 | **10件**（`config.json`） | 暴走防止 |
| 同一店舗への再送 | **禁止** | `sent_at` があれば送らない |
| `do_not_contact: true` | **除外** | 一度断られた相手に二度送らない |
| 除外業種 | **必須** | `brand/LEGAL.md` §2 の除外リストに該当する店は対象外 |
| 送信記録 | **必須** | `outreach.md` に全文と日時を残す |
| 苦情が来たら | **全停止** | 残りを送らず、ユーザーに報告して判断を仰ぐ |

---

## 手順

### 1. 対象を選ぶ

`prospects/*/info.json` から次を全て満たす店を選ぶ。

- `status` が `published`
- `sent_at` が無い
- `do_not_contact` が `true` でない
- 本日の送信数が `daily_send_cap` 未満
- **`brand/LEGAL.md` §2 の除外リストに当てはまらない**
  （株式会社／FC／士業／医療機関／接骨院・鍼灸院・整体院／薬局）

除外に当てはまった店は `status: "excluded"` と `"excluded_reason"` を書いて飛ばす。

### 2. はがきを作る（本命）

```bash
python3 scripts/make_postcard.py <slug>
```

`prospects/<slug>/postcard.html` ができます。
ブラウザで開いて印刷（はがきサイズ100×148mm）。QRコードは自動で入ります。

**文面に必ず入れる要素：**

1. **ミセバの〇〇**と名乗る（「株式会社」「代表」「弊社」は使わない）
2. Googleマップで見つけたこと（どこから来たかを隠さない）
3. **すでに試作ページを作ってあること**と、QRコード／短縮URL
4. **AIを使って作った試作である**こと
5. 一方的に送っていることへの配慮
6. **不要なら連絡してもらえれば二度と送らない／すぐ消す**旨
7. 費用の目安
8. **LINEのQR**（`make_postcard.py` が自動で入れる）

**入れてはいけない要素：**

- 効果の断定（「必ず問い合わせが増えます」）
- 期限を切った煽り（「今週中なら無料」）
- 専門用語（LP / SEO / CVR / レスポンシブ）
- 相手の弱点の指摘（「ホームページが無くて損をしています」）
- 「無料」を強調した釣り

### 3. 電話台本を作る（はがきが使えない／反応が無いとき）

```bash
python3 scripts/make_postcard.py <slug> --phone
```

`prospects/<slug>/phone_script.md` ができます。

**電話の唯一のルール：その場で売らない。**
用件は「試作を見てもらう方法を聞く」だけ。相手が「見てみたい」と言ったら、
はがきを送るか、その場で相手が指定した方法でURLを伝える。

### 4. 自己チェック（送る前に必ず）

- [ ] 「株式会社」「合同会社」「代表」「弊社」「当社」を使っていないか
- [ ] 効果を断定していないか
- [ ] **店名が合っているか**（別の店の名前が混ざっていないか）★最悪の事故★
- [ ] 住所が合っているか（宛先と中身が一致しているか）
- [ ] URLが実際に開けるか
- [ ] 「不要ならご連絡ください」が入っているか
- [ ] 除外業種に当てはまっていないか

### 5. 記録する

`prospects/<slug>/outreach.md` に追記。

```markdown
## 2026-08-18 10:32
- 手段: はがき
- 宛先: 〇〇工務店（東京都〇〇区…）
- 試作サイト: https://.../p/xxxx/
- 文面:
  （全文をそのまま）
```

`info.json` に `"sent_at"`, `"status": "contacted"`, `"channel": "postal"` を書く。

## 返信・反応が来たら

| 相手の反応 | やること |
|---|---|
| 興味あり | `status: "interested"`。**その場で契約しない。**見積を作って書面で出す |
| 断り | `do_not_contact: true`、`status: "declined"`。**試作サイトも消す** |
| 削除要求 | `publish-preview` の「取り下げるとき」を**その日のうちに**実行 |
| 苦情・怒り | **全ての送信を止め、ユーザーに報告する** |

### 「興味あり」の次にやること

1. 見積を作る（制作費・修正回数の上限・月額の内容・解約方法・著作権の扱い）
2. **書面（PDFかメール）で出す。口頭で決めない**
3. 相手が承諾したら着手

`brand/LEGAL.md` §3 を必ず読み直すこと。
